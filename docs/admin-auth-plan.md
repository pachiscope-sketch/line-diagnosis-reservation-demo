# 管理画面の認証設計メモ

このデモでは、管理画面 `/admin` で診断回答、予約、会員情報、CSV出力、連携状態を確認できます。

ポートフォリオ公開時は見せやすさを優先していますが、本番案件では必ず認証と権限設計が必要です。

## このデモの簡易保護

`ADMIN_PASSWORD` を設定すると、`/admin` と `/api/admin-data` に簡易Basic認証がかかります。

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me
```

未設定の場合は、営業デモとして未保護のまま表示されます。

この仕組みはポートフォリオ用の簡易保護です。本番の個人情報管理には、より強い認証設計を推奨します。

## 選択肢1: Supabase Auth

Supabase Authで管理者とスタッフをログインさせる構成です。

- 管理者: 全データ閲覧、CSV出力、設定変更
- スタッフ: 予約確認、来店処理、ポイント付与
- LINEユーザー: 自分の会員証、予約情報のみ閲覧

SupabaseのRLSと組み合わせることで、権限ごとに参照範囲を制限できます。

## 選択肢2: Basic認証

小規模な営業デモや一時的な検証環境では、Basic認証でも最低限の保護になります。

メリット:

- 実装が軽い
- Vercel環境変数だけで設定できる
- 発注者デモURLを簡単に守れる

注意点:

- ユーザーごとの権限管理には向かない
- パスワード共有になりやすい
- 本番運用では監査ログや退職時の権限削除が弱い

## 選択肢3: Vercel Middleware

このデモではVercel MiddlewareでBasic認証を実装しています。

保護対象:

```text
/admin
/api/admin-data
```

本番では、API全体の保護範囲、CSV出力、予約詳細、会員情報の参照権限まで設計します。

## 本番案件で追加すべきこと

- 管理者ログイン
- スタッフログイン
- 店舗ごとのデータ分離
- Supabase RLS
- 操作ログ
- 個人情報の削除依頼対応
- CSV出力権限の制限
- Slack通知先の権限管理
- LINE User IDの利用目的と保存期間の明記
